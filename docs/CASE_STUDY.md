# Product case /case

The case describes the development feedback and behavior implemented in Tyter.
The project author confirmed three product generations: 1.0 (screenplay),
2.0 (outline), 3.0 (storyboards). These are not package versions or build counts.

Conversion, product and marketing blocks are an instrumentation plan, not
measured results. Dashes mean no baseline yet. Do not replace them with
estimates presented as actual results. Once data exists, include the period,
sample, channel/cohort definition and source alongside each value.

The candidate value metric is weekly active writers saving a meaningful edit.
Activation is a first saved non-empty scene. D7/D30 refer to exact-day editing
retention among activated users; Free-to-PRO uses confirmed first payments.
Agree on identity, consent and attribution before collecting these events.
Do not send screenplay content or clipboard data to analytics.

The page does not install an analytics collector. Its diagrams are fictional
illustrations, explicitly labelled as such. They use no user documents.

Headings and metric values reuse the welcome Emotional animation, once after
scrolling and visibility. Body copy is static. Reduced motion disables motion.
The route prefetches on navigation intent; diagrams load 600px before entering
the viewport with reserved loading skeletons.
