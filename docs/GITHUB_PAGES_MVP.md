Для вашей распакованной папки **D:/Tyter/publication/tyterapp.github.io** используйте [пошаговую инструкцию повторной публикации через Git Bash](GITHUB_PAGES_UPDATE.md). Она сохраняет историю существующего репозитория и объясняет копирование исходников, отправку изменений и запуск публикации.

## Настройки публикации

В **Settings → Pages → Source** выберите **GitHub Actions**. Проект содержит `.github/workflows/pages.yml` с названием **Publish Tyter MVP**. Он запускается после отправки в `main` и вручную через **Actions → Run workflow**. [Публикация через GitHub Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Список ключей хранится в вашем уже созданном repository secret **TYTER_PRO_CODES**: **Settings → Secrets and variables → Actions → Secrets**. Значение содержит одну пару на строку:

```text
[ABC123][person@example.com]
[DEF456][]
```

Это примеры формата. Используйте свои ключи из шести латинских букв или цифр и email пользователей. Пустой или некорректный email доступа не даёт. Секрет передаётся в сборку через переменную окружения; исходники не содержат реального списка. [Секреты GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

Workflow создаёт папку `github-pages`, отдельные `index.html` для маршрутов, корневой `404.html` и `codes-for-pro.txt` с проверочными хешами. На сайт публикуется эта папка целиком. Отдельный сервер не требуется. Установщики в этом этапе не обновляются.

## Проверка доступа PRO

Браузер читает https://tyterapp.github.io/codes-for-pro.txt. Файл содержит хеши пар «ключ + email» и метки неназначенных ключей; исходные коды и email не публикуются. Проверка не обращается к sergeybukharev.github.io.

Верная пара открывает PRO. Неизвестный ключ, чужой email, пустой email или `null` в секрете не дают доступа. Регистр email и ключа не важен. Вход запоминается в браузере как хеш пары без установленного срока истечения; проверка происходит при открытии, раз в минуту и при возвращении во вкладку. Сохранённые сессии предыдущего формата остаются совместимыми, если та же пара есть в секрете.

Для проверки нужен интернет. При недоступности файла сохранённая сессия остаётся для повторной проверки; удалённая из опубликованного списка пара больше не допускается. Очистка данных сайта или другой браузер требуют повторного входа.

Хеши позволяют не публиковать исходные коды и адреса, но проверка в JavaScript остаётся ограничением статического MVP и не заменяет серверную защиту.

## Обновление списка ключей

1. Нажмите карандаш рядом с **TYTER_PRO_CODES** в настройках репозитория.
2. Замените список целиком и сохраните. Для отзыва доступа удалите строку или очистите email.
3. Запустите **Actions → Publish Tyter MVP → Run workflow → main**.
4. Дождитесь зелёного статуса.

Изменение секрета не запускает сборку автоматически. До повторной публикации на сайте действует прежний список. Коммит для изменения секрета не нужен. Опубликованный `codes-for-pro.txt` вручную не редактируется.

## Документы пользователей

Сценарии, комментарии, компоненты, реквизит, аутлайн и история сохраняются на устройстве пользователя. Они не отправляются в репозиторий или на GitHub Pages. Chrome и Edge на HTTPS позволяют выбрать папку для автосохранения TYT в PRO. В других браузерах копию можно скачать в TYT вручную.

Обновление приложения на том же домене не требует очистки данных. Важные проекты заранее сохраните в TYT. Хранилища разных доменов независимы.

## Локальная проверка

Для проверки приложения без списка ключей, с Node.js 22+:

```bash
ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci
npm run build
```

Для полного локального предпросмотра Pages нужен ваш локальный `codes-for-pro.txt` в корне проекта, в том же формате, что секрет. Файл исключён из Git; не добавляйте его принудительно. Если локальной копии списка нет, используйте сборку в GitHub Actions вместо выгрузки секрета.

```bash
npm run site:github
npm run site:github:preview
```

Предпросмотр: http://127.0.0.1:4181/. Проверка PRO обращается к опубликованному списку на tyterapp.github.io, поэтому предварительно опубликуйте сайт. Остановить предпросмотр можно через Ctrl + C.

Автоматические проверки собранного сайта:

```bash
npm run test:pages
```

Они проверяют маршруты, вход, ошибки, сохранение сессии и повторную проверку с тестовыми данными без реальных ключей пользователей.

## Ошибки публикации

- **Нет TYTER_PRO_CODES:** проверьте существование и точное имя repository secret в tyterapp/tyterapp.github.io. Workflow должен использовать `secrets.TYTER_PRO_CODES`.
- **Ошибка формата строки:** исправьте список в секрете, одна пара `[ключ][email]` на строку, и повторите workflow.
- **Старая версия сайта или списка:** дождитесь успешной публикации последнего коммита или повторного запуска после изменения секрета. Обновите вкладку через Ctrl + F5.
- **Файл проверки не читается:** проверьте интернет и https://tyterapp.github.io/codes-for-pro.txt. Он должен содержать JSON с `version`, `pairs` и `unassigned`. Старый файл с открытыми кодами несовместим с текущей проверкой: запустите новый workflow.
- **Ключ не подходит:** email и код должны совпасть с одной строкой секрета; строка без email доступа не даёт.
