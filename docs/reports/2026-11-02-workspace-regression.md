# Проверка сценария, раскадровки и сохранения Tyter

Дата: 2 ноября 2026 года. Изменения относятся к основному редактору в `src/`.

## Исправления интерфейса и работы с кадрами

- `Ctrl + Shift + C` скрывает метки комментариев и рисунки замечаний поверх кадра. Повторное нажатие возвращает их. Текст переписки сохраняется; открытая переписка остаётся доступной в панели.
- График драматичности открывается из сценария. В раскадровке и редакторе кадра его кнопки нет. Выбор сцены в раскадровке показывает структуру сцены; отдельные кадры остаются в карточках сцен.
- Редактор кадра использует собственную панель слоёв, комментариев и AI. Кнопка возврата ведёт к раскадровке. Убрана лишняя пустая мобильная панель поверх холста.
- Компонент можно перетащить из библиотеки в конкретное место текста сценария. Вставляется актуальное имя и ссылка на существующий компонент. Отключённые и удалённые компоненты не вставляются. Работают отмена, возврат и сохранение.
- В поиске есть области «Сценарий» и «Раскадровка». Находятся сцены «Без названия» / «Untitled», кадры, подписи, настройки, слои и комментарии, включая сохранённые варианты сцен. Карточки показывают миниатюру, страницу, сцену, вариант и номер кадра. Большая выдача загружается порциями.
- Презентация принимает кадры с видимыми рисунками и изображениями в слоях без фоновой картинки. Скрытые слои и одни лишь комментарии не делают пустой кадр пригодным к воспроизведению.
- Вставка картинки в открытый редактор кадра создаёт выбираемый слой. Она не открывает диалог вставки отдельных кадров и не перехватывает вставку текста в поля. Доступны перемещение, переименование, порядок, видимость и удаление слоёв.
- Формат холста соответствует формату кадра. На узком экране панель располагается под холстом, инструменты доступны горизонтальной прокруткой. Проверка выполнена в браузерной эмуляции.
- Миниатюры, презентация, PNG-последовательности и публичный просмотр учитывают слои. Вставка новых кадров в раскадровке не заменяет фон существующего нарисованного кадра.
- `Ctrl + 0` возвращает масштаб сценария к 100%, раскадровки — к стандартному масштабу соответствующего экрана.

## Подготовка генерации кадров

Контекст генерации содержит сцену, выбранного персонажа, локацию и настройки кадра, включая крупность, свет и формат. Предусмотрен отдельный контракт провайдера, чтобы позже подключить API без изменения модели документа. Новый платный сервис не подключался. Проверки не отправляли пользовательские материалы внешним генераторам. Существующий интерфейс AI Horde сохранён.

## Производительность и память

Убраны подтверждённые лишние операции:

- Автоматические ссылки компонентов используют неизменяемые узлы абзацев повторно: при правке одного абзаца тест на 300 абзацах проверяет только изменившийся текст. Изменение самих компонентов обновляет все нужные ссылки.
- Возврат собственного текста из React в редактор больше не требует сериализации полного документа для сравнения.
- Подсчёт слов повторно использует результаты неизменённых абзацев вместо преобразования двух полных документов в JSON.
- Оформление стрелок кешируется по неизменяемым узлам. Тест на 300 абзацах подтверждает один повторный анализ при изменении одного абзаца; перемещение позиций и оформление стрелок сохраняются.
- Закрытый поиск, закрытая раскадровка и индекс отсутствующих комментариев не пересчитываются при каждом вводе. Проверка истории не сериализует все изображения и слои при каждом обновлении интерфейса. Изменение масштаба просмотра не создаёт содержательную редакцию документа.

Ограниченный стресс-тест опубликованной сборки: 451 абзац, 80 компонентов, замедление CPU в 4 раза, ввод 24 символов, отмена/возврат, 20 переключений масштаба 100–200%, сохранение и перезагрузка.

Это один воспроизводимый замер, а не гарантия скорости на каждом Android. На таком длинном документе с CPU ×4 ввод всё ещё требует заметного времени. Рост относительно начальной памяти включает прогретые кеши и историю отмены; повторная серия масштабирования не показала сопоставимого дальнейшего роста. Тест не доказывает отсутствие любых утечек. Встроенные изображения, история изменений и DOM длинного документа по-прежнему влияют на память. Крупные коллекции фотографий не выдаются за проверенные этим текстовым стресс-тестом.

Скрипт повторения: `node checks/workspace-stress.mjs http://127.0.0.1:4181 report.json`. Численные результаты сохранены рядом в `2026-11-02-workspace-stress.json`. Отладочные замеры React не использовались как обещание скорости опубликованной версии.

## Хранилище, история и кеш

Проверены действующие очереди записи локальных файлов и браузерного хранилища, клонирование сохраняемого состояния, контроль ревизии библиотеки и восстановление из истории. Эти механизмы сохранены; массовая очистка данных и миграция формата TYT не выполнялись. Нужные новые поля слоёв проходят проверку при импорте и сохраняются в экспортируемом документе.

Подтверждено сохранение полного TYT в выбранную локальную папку, повторное открытие и восстановление текста после перезагрузки. Для автоматизации использовалась отдельная папка внутри браузерного хранилища, а не реальные пользовательские документы. Совместная одновременная работа в нескольких вкладках не является реализованным multiplayer; серверная синхронизация в этом изменении не добавлялась.

В офлайн-кеш добавлены ресурсы печатной машинки. Версия кеша зависит от содержимого публичных ресурсов; изменение картинки меняет версию. Сохраняется текущая и одна предыдущая версия ресурсов, чтобы открытая вкладка могла закончить работу после обновления. Пользовательские документы и список доступа PRO не входят в этот кеш. Проверены запуск без интернета, запись текста, перезагрузка и первая загрузка экспортера XLSX уже офлайн.

## Проверки и границы результата

- 117 тестов модели данных: пройдены.
- Основной набор: 43 из 44 браузерных сценариев прошли общим прогоном. Проверка локальной папки остановилась по общему времени; её ожидание загрузки и чтение ещё не записанного файла исправлены. Отдельная проверка прошла.
- Стрелки, персонажи и пустой старт: 13 из 15 прошли общим прогоном. Два сценария остановились по времени при параллельной нагрузке; оба прошли отдельно без изменения приложения.
- История в светлой/тёмной теме на ПК и 320 px: 4 из 4 пройдены.
- Офлайн-сценарии: 2 проверены. Проверка XLSX обновлена для открытия вкладки «Инфо» перед выбором отчёта и прошла отдельно.
- Итого проверены 65 различных браузерных сценариев с учётом указанных отдельных повторов. Это выбранный регрессионный набор, не весь исторический набор проекта.
- `npm run build` и `npm run site:github`: завершились успешно. Предупреждение о крупном основном JS-файле сохраняется: около 1,09 МБ до сжатия / 357 КБ gzip. Полное разделение приложения на дополнительные части не выполнялось в рамках этой правки.
- Контроль неизменности изолированной версии: 417 файлов подтверждены исходным манифестом. Исходники, ресурсы и манифест Dilda Mode не изменялись.

Браузерные проверки выполнялись в Edge/Chromium на Windows, включая мобильные размеры и замедление CPU. Физический Android/Chrome и установка на реальном телефоне не проверялись. Живая публикация в GitHub не выполнялась; локальная успешная сборка не подтверждает состояние удалённых секретов и GitHub Actions.

## Архив для GitHub

Обновляется `publication/tyter-github-pages-source.zip`: исходники, проверки, документация и исходная изолированная версия. Настоящие ключи PRO, `.env`, пользовательские документы и журналы проверок в архив не входят. Сборка проверялась с синтетическим тестовым ключом.

Для существующего репозитория, где `frozen/` уже присутствует, сохраняется текущий сценарий копирования. При подготовке совершенно нового checkout необходимо также перенести каталог `frozen/`, присутствующий в архиве: прежний список `cp` его не содержит. Реальный рабочий Git-репозиторий пользователя не изменялся и не отправлялся на GitHub.
